# Local AI RAG Assistant

Μια τοπική εφαρμογή **Retrieval-Augmented Generation (RAG)** χτισμένη με Streamlit, Docker και LM Studio, η οποία επιτρέπει την υποβολή ερωτήσεων και την άντληση πληροφοριών απευθείας από τοπικά αρχεία PDF.

---

## Προαπαιτούμενα (Prerequisites)

Για να τρέξετε την εφαρμογή τοπικά στον υπολογιστή σας, θα χρειαστείτε:
1. **Docker & Docker Compose** (π.χ. Docker Desktop για macOS/Windows ή Docker Engine για Linux).
2. **LM Studio** για την τοπική εκτέλεση του γλωσσικού μοντέλου (LLM).

---

## Ρύθμιση του LM Studio

Πριν ξεκινήσετε το Docker container, βεβαιωθείτε ότι το LLM τρέχει τοπικά:
1. Ανοίξτε το **LM Studio** και κατεβάστε το μοντέλο που επιθυμείτε (π.χ. `nvidia/nemotron-3-nano-4b`).
2. Πηγαίνετε στην καρτέλα **Local Server** (ή στα **Settings** του server).
3. Φορτώστε το μοντέλο πηγαίνοντας στην καρτέλα **Local Model API** και επιλέξτε το **Local API Server** ως **Running** 

---

## Εντολές Docker (Build, Run & Stop)

Τοποθετήστε τα αρχεία `.pdf` που θέλετε να αναλύσετε μέσα στον φάκελο `pdfpath/` του project.

* **Build και εκκίνηση της εφαρμογής (με ζωντανά logs στο τερματικό):**
  ```bash
  docker compose up --build
  ```

* **Build και εκκίνηση στο παρασκήνιο (background / detached mode):**
  ```bash
  docker compose up -d --build
  ```

* **Προβολή των logs (όταν τρέχει σε background mode):**
  ```bash
  docker compose logs -f
  ```

* **Τερματισμός και καθαρισμός των containers:**
  ```bash
  docker compose down
  ```


Αφού ξεκινήσει, η εφαρμογή είναι προσβάσιμη στον browser σας στη διεύθυνση: `http://localhost:8501`

## Αρχιτεκτονική & Εξήγηση Κώδικα

Η εφαρμογή υλοποιεί έναν πλήρη μηχανισμό RAG χωρίς εξωτερικές vector databases, βασισμένο σε μαθηματικά μοντέλα ανάκτησης πληροφορίας:

### 1. Εξαγωγή Κειμένου & Chunking
* **PDF Parsing:** Η εφαρμογή σαρώνει τον φάκελο `pdfpath` και χρησιμοποιεί τη βιβλιοθήκη `pypdfium2` για γρήγορη εξαγωγή κειμένου από κάθε σελίδα. *(Σημείωση: Αρχεία PDF που αποτελούνται αποκλειστικά από σαρωμένες εικόνες χωρίς OCR παραλείπονται αυτόματα).*
* **Chunking:** Επειδή τα γλωσσικά μοντέλα έχουν περιορισμένο παράθυρο μνήμης (context window) και η αναζήτηση σε ολόκληρα έγγραφα μειώνει την ακρίβεια, το εξαγόμενο κείμενο τεμαχίζεται σε μικρότερα, διαχειρίσιμα κομμάτια (**chunks**). Με αυτόν τον τρόπο, το σύστημα μπορεί να εντοπίσει με ακρίβεια τη συγκεκριμένη παράγραφο που περιέχει την απάντηση.

### 2. Custom TF-IDF Vectorizer
Για να μετατραπούν τα chunks κειμένου σε αριθμητικά διανύσματα (vectors) που μπορεί να επεξεργαστεί ο υπολογιστής, χρησιμοποιείται ένας custom **TF-IDF (Term Frequency - Inverse Document Frequency)** vectorizer:
* **`fit()`:** Αναλύει όλα τα διαθέσιμα chunks, χτίζει το dictionary **vocabulary** των μοναδικών λέξεων και υπολογίζει το **IDF** (Inverse Document Frequency) για κάθε όρο:
  $$\text{IDF}(t) = \log\left(\frac{N}{\text{df}(t)}\right)$$
  όπου $N$ ο συνολικός αριθμός των chunks και $\text{df}(t)$ ο αριθμός των chunks που περιέχουν τον όρο $t$. Έτσι, λέξεις που εμφανίζονται παντού (όπως άρθρα ή συνδετικές λέξεις) λαμβάνουν μικρότερο βάρος, ενώ σπάνιοι, σημαντικοί όροι λαμβάνουν υψηλότερο βάρος.
* **`transform()`:** Μετατρέπει οποιοδήποτε κείμενο (είτε ένα chunk είτε την ερώτηση του χρήστη) σε ένα διάνυσμα διαστάσεων ίσων με το μέγεθος του λεξιλογίου. Κάθε θέση του διανύσματος παίρνει την τιμή $\text{TF}(t, d) \times \text{IDF}(t)$, αποτυπώνοντας τη σημασία κάθε λέξης στο συγκεκριμένο απόσπασμα.

### 3. Cosine Similarity & Top-$k$ Retrieval
Όταν ο χρήστης υποβάλλει μια ερώτηση (query) μέσω του Streamlit:
1. Το query μετατρέπεται σε διάνυσμα $\mathbf{q}$ μέσω της μεθόδου `transform()` του vectorizer.
2. Υπολογίζεται η **ομοιότητα συνημιτόνου (Cosine Similarity)** ανάμεσα στο διάνυσμα της ερώτησης $\mathbf{q}$ και στο διάνυσμα κάθε chunk $\mathbf{c}_i$:
   $$\text{similarity}(\mathbf{q}, \mathbf{c}_i) = \frac{\mathbf{q} \cdot \mathbf{c}_i}{\|\mathbf{q}\| \|\mathbf{c}_i\|}$$
   Το αποτέλεσμα κυμαίνεται από $0$ (καμία σχέση) έως $1$ (απόλυτη ταύτιση κατεύθυνσης/θεματολογίας), ανεξάρτητα από το μήκος του κειμένου. Στην πράξη, η τιμή κυμαίνεται μεταξύ $0.30-0.40$.
3. **Retrieve Top-k:** Τα chunks ταξινομούνται σε φθίνουσα σειρά με βάση το σκορ ομοιότητας και επιλέγονται τα **$k$ πιο σχετικά** αποσπάσματα. Αυτά ενσωματώνονται δυναμικά στο prompt που αποστέλλεται στο τοπικό LLM του LM Studio, ώστε το μοντέλο να συνθέσει την τελική απάντηση βασιζόμενο αποκλειστικά στα δεδομένα των εγγράφων σας.
